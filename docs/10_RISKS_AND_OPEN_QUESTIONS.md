# Риски, ограничения и открытые вопросы

Анализ по коду репозитория после этапов 0–17. Роадмап-факт:
`07_ROADMAP_MVP.md`.

## 1. Регуляторные / платформенные риски

### Верификация Google Ads Developer Token

**Статус: процесс, не код.** Токен задаётся через `GOOGLE_ADS_DEVELOPER_TOKEN`
и уходит в Connector Layer. Сама верификация у Google — внешний процесс
(описание продукта, демо). В коде его не автоматизируем.

### Лимиты API и антифрод платформ

**Закрыто в коде (частично, достаточно для текущего цикла):**

- Живые вызовы Яндекс Директа и Google Ads идут через
  `ProjectApiLimiter` с ключом `{platform}:{projectId}` (по умолчанию 200 мс).
- Соседние `project_id` могут идти параллельно.
- Пустой `projectId` на живом вызове — ошибка. Моки лимитер не используют.
- Повтор при 429/5xx заново занимает слот очереди.
- Подряд идущие 429 на одном ключе удваивают паузу очереди (400 мс → …
  до 4 с); успешный ответ сбрасывает бэкофф. Пока троттлинг держится,
  следующие вызовы той же платформы/проекта отступают, а не бьют
  фиксированными 200 мс.
- 429 создаёт ops-alert `platform_rate_limit` без токенов в тексте.

### Ответственность агентства за ИИ в кабинете

**Закрыто в продукте (юридический минимум, не замена договора с юристом):**

- Страница `/terms`: бюджет и ошибки запуска — на организации пользователя;
  автопубликации нет; кампании создаются на паузе; автопилот только opt-in.
- Регистрация требует `acceptTerms: true`; в `users.terms_accepted_at`
  пишется момент согласия.
- Чекбокс публикации ссылается на `/terms`.

Полный юридический договор и страхование — вне репозитория.

## 2. Технические риски

### Качество кластеризации / правок человека

**Закрыто метрикой правок, без отдельного UI редактирования кластеров**
(кластеры read-only; правка — через тексты объявлений):

- `GET /projects/:id/creatives` отдаёт `quality.creatives` и `quality.clusters`.
- `acceptedShare` = доля сущностей **без** ручной правки
  (`CreativeStatus.edited`).

**Смысловая корректность ядра (не то же самое, что `acceptedShare`):**

- Диагностика: `npm run qa:semantic`, эталоны в `qa/semantic/fixtures`,
  baseline — `docs/12_SEMANTIC_QA_BASELINE.md`.
- Recall / precision по размеченному мусору / разделение кластеров
  (intra−inter cosine). Без порога CI: смотреть глазами.

### Unit-экономика LLM в Reporting

**Закрыто:** `GET /projects/:id/reports` включает `llmUsage` (сводка по
`llm_call_logs` этого `project_id`, без полного промпта). KPI «LLM $».
Детализация — «Расходы LLM».

### Изоляция Connector Layer

**Соблюдается:** агенты и оркестратор не импортируют SDK платформ. Живые
HTTP-вызовы — только в `LiveYandexDirectApi` / `LiveGoogleAdsApi`.

## 3. Продуктовые риски

### Human-in-the-loop и объяснимость

**Закрыто для текущего цикла:**

- Публикация и автопилот — только после явного согласия в UI.
- Ключи: интент + `source`. Объявления: кластер + бейдж «правлен вручную».
- Оптимизация: `rationale` на экране.

### Конкуренция с Мастером кампаний / PMax / биддерами

Продуктовая формулировка, не код: ценность — полный цикл и две платформы.
Performance Max в коде не дублируем.

## 4. Открытые вопросы

| # | Вопрос | Статус |
|---|--------|--------|
| 1 | Какая платформа первая | Закрыто: обе, через Connector Layer |
| 2 | Монетизация / `organizations.plan` | **Открытый пробел.** Колонка есть (`free`), но нет тарифов, лимитов плана, Stripe, смены `plan`. Это не решение «отложено намеренно» и не закрытый отказ от биллинга — просто не реализовано. Без отдельной задачи продукт нельзя продавать как SaaS с оплатой. |
| 3 | Субклиенты агентства | Закрыто: `project_access`, роль `client`, white-label |
| 4 | Автономность ежедневных правок | Закрыто: автопилот opt-in, только pause / budget / negatives; `createCampaign` запрещён |
| 5 | CRM / сквозная аналитика | Закрыто: AttributionConnector; телефоны только hash |

## 5. Что сознательно не делаем (политика продукта)

- Верификационный workflow Google Developer Token в коде.
- Автопубликация кампаний (оркестратор, очередь, автопилот).
- Отдача полного LLM-промпта в UI (в БД промпт пишется, в REST — preview).

Биллинг сюда **не** входит: см. п. 2 таблицы в разделе 4.

### Не пройдено (блокер или процесс вне CI)

- [ ] **Биллинг:** нет оплаты, квот плана, смены `organizations.plan`
- [ ] **Живой прогон на песочнице / тестовом кабинете Яндекс Директа
      человеком** (не mock): бриф → пайплайн → чекбокс → кампания
      **Suspended/Off** в кабинете; проверка ошибки политики Директа в UI.
      Чеклист в корневом `README.md`, раздел «Ручной прогон Connector».
- [ ] **Живой прогон Google Ads** (Developer Token + тестовый customer):
      то же, статус PAUSED в кабинете
- [ ] Верификация Google Ads Developer Token (процесс Google)
- [ ] Юридический договор агентства / страхование ответственности за ИИ
- [ ] Секреты и ключи только в secret manager прод-среды (не `.env` на диске)
- [ ] Наблюдаемость прода: агрегатор логов, алерты на падение очереди
      (в коде есть `ops_alerts`, внешнего paging нет)

Пока не закрыты живой Яндекс и биллинг, платформу нельзя считать готовой
к платным кабинетам клиентов, даже если E2E на моках зелёный.
