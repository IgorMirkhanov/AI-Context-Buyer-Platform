# Semantic Agent — регрессионный QA и baseline

Диагностика смысловой корректности ядра, отдельно от метрики `quality`
(доля объявлений/кластеров без ручной правки). Это **не** Playwright и
**не** unit-тест с порогом pass/fail: контекстолог смотрит цифры и списки
расхождений.

Запуск (мок Wordstat + `HeuristicSemanticLlm`, без кабинета и без LLM API):

```
npm run qa:semantic
```

Эталоны: `qa/semantic/fixtures/*.json`. Сравнение: `packages/agents/src/semantic/qa-compare.ts`.

## Откуда эталоны (не от LLM)

Новых ключей модель не сочиняла. Три фикстуры собраны из того, что уже
лежит в репозитории:

| id | Бриф | Ключи эталона |
|----|------|----------------|
| `asus-gaming` | `semantic-pipeline.spec.ts` | фразы из `docs/03_DATA_MODELS.md` §3 + фразы spec + шаблоны `MockKeywordIdeasProvider` на человеческий УТП |
| `asus-hp-brands` | имена кластеров из `copywriting-pipeline.spec.ts` / `campaign-builder.spec.ts` | `купить asus rog`, `купить hp omen` и шаблоны мока на эти две строки |
| `office-laptops` | поля формы `e2e/platform.spec.ts` | точная строка УТП + шаблоны мока на неё |

У каждой фразы в JSON есть поле `source`. Расширять эталон нужно вручную
(добавить ключ в `gold` или правило в `irrelevant`), а не генерировать
«идеальное ядро» чатом.

Разовая разметка мусора (`irrelevant`): сервисный шаблон `{seed} ремонт`
из мока Wordstat, минусы брифа (`бесплатно`, `скачать`, `торрент`), сегмент
ЦА как запрос, хост `website_url` как маска.

## Метрики

- **Покрытие (recall)** — какая доля эталонных ключей нашлась у агента
  (нормализация: trim, нижний регистр, схлопывание пробелов).
- **Точность (precision)** — `1 − (размеченный мусор / все ключи агента)`.
  В штраф идут только правила `irrelevant`. Фразы «не в эталоне и ещё не
  размечены» печатаются списком и **не** портят precision, пока их не
  перенесут в gold или irrelevant.
- **Разделение кластеров** — среднее косинусное сходство (те же
  hash-n-gram эмбеддинги, что у агента) внутри кластера минус среднее
  сходство случайных пар из разных кластеров. Выше — лучше отделение.

## Baseline (2026-08-28)

Прогон: `HeuristicSemanticLlm` + `MockKeywordIdeasProvider`, коммит рабочей
копии после введения `npm run qa:semantic`. Повторить команду после смены
масок, мока Wordstat или эмбеддингов и сравнить с таблицей.

| Фикстура | Recall | Precision | Intra − inter | Эталон / агент |
|----------|--------|-----------|---------------|----------------|
| asus-gaming | 58.3% (7/12) | 43.8% (мусор 18/32) | 0.4031 | 12 / 32 |
| asus-hp-brands | 100% (10/10) | 43.8% (мусор 18/32) | 0.3635 | 10 / 32 |
| office-laptops | 100% (7/7) | 29.2% (мусор 17/24) | 0.4132 | 7 / 24 |

Что baseline уже показывает (это ожидаемые дыры эвристик, не баг прогона):

1. **Recall asus-gaming 58%** — агент не достаёт человеческие формулировки
   из docs/03 (`купить игровой ноутбук asus`, `ноутбук asus rog обзор`) и
   spec (`купить ноутбук asus`, `ноутбук asus обзор`, `купить asus`): мок
   расширяет только маски из УТП/ЦА/хоста, без «rog» и без сингуляра.
2. **Precision 29–44%** — `masksFromBrief` кормит Wordstat сегментом ЦА и
   куском домена; мок добавляет `{seed} ремонт`. Кластеры «геймеры 18-30»
   и `e2e-shop` / `asus-gaming` — шум.
3. **Кластеры** — разделение ~0.36–0.41 на hash-n-gram; на `asus-hp-brands`
   «hp omen заказать» отвалился в отдельный кластер из одного ключа.

JSON-срез для скриптов: `npm run qa:semantic -- --json`.
