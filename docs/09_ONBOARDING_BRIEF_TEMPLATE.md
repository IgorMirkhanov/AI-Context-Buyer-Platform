# Шаблон онбординг-брифа и чек-лист данных

Этот документ — то, что нужно собрать у рекламщиков/клиентов **до** запуска
проекта на платформе. Используется для (а) наполнения UI формы брифа,
(б) валидации, что новый клиент готов к подключению.

## 1. Доступы (заполняются через UI-флоу, не текстом)

- [ ] Подключение рекламного кабинета через "Подключить Яндекс Директ" /
      "Подключить Google Ads" (OAuth) — см. `04_API_INTEGRATIONS.md`.
- [ ] Для агентств: подтверждение, что клиентский аккаунт доступен через
      агентский/MCC-доступ, а не только через личный логин конечного клиента.

## 2. Маркетинговый бриф (текст / форма)

- [ ] Описание продукта/услуги.
- [ ] 3-5 ключевых УТП.
- [ ] Ценовой сегмент (эконом/средний/премиум) — влияет на минус-слова
      и тон объявлений.
- [ ] Портреты ЦА: сегменты, боли, возражения, критерии выбора.
- [ ] Стоп-слова и юридические ограничения (запрещённые формулировки,
      нишевые ограничения — например, реклама медицины/финансов имеет
      отдельные требования площадок).
- [ ] География показов и часы работы/обработки заявок.
- [ ] Целевая стоимость лида (target CPL) и/или ROAS.

## 3. Данные предыдущих кампаний (если есть) — XLSX/CSV/JSON

- [ ] Существующее семантическое ядро с частотностью и историческим CTR
      (если контекстолог уже вёл проект раньше).
- [ ] Список минус-слов, накопленный за время ведения.
- [ ] Архив объявлений с пометками, какие показали лучшую конверсию.
- [ ] Список площадок-исключений (для РСЯ/КМС) — неэффективные сайты/приложения.

## 4. Аналитика (JSON / доступ к кабинетам аналитики)

- [ ] Список настроенных целей в Яндекс Метрике / Google Analytics —
      названия, ID, тип (форма/звонок/покупка).
- [ ] Стандарт UTM-разметки компании (если уже принят), иначе —
      предложить стандартный шаблон (см. `03_DATA_MODELS.md`, раздел 2).
- [ ] Доступ (read-only) к Яндекс Метрике/GA для проверки корректности целей.

## 5. Креативы

- [ ] Требования к изображениям/видео (форматы, соотношения сторон).
- [ ] Ссылка на хранилище с готовыми баннерами, если есть.
- [ ] Согласие/уточнение — можно ли использовать генеративные изображения
      (Midjourney/FLUX/DALL-E) при отсутствии готовых креативов.

## 6. Ограничения по запуску

- [ ] Дневной/месячный бюджет и жёсткие лимиты, которые нельзя превышать.
- [ ] Требуется ли ручное утверждение перед первым запуском кампании
      (в MVP — да, всегда).
- [ ] Контактное лицо для эскалации, если `Validation Agent` находит
      юридически спорную формулировку и не может решить сам.

## Итоговый формат для загрузки в систему

Все пункты выше маппятся напрямую в JSON-схему `project_briefs.payload_json`
из `03_DATA_MODELS.md`, раздел 2 — при проектировании формы онбординга
использовать эту схему как источник истины для полей формы.
