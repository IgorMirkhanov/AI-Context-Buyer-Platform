# Работа с Cursor над этим проектом

## 1. Готовый `.cursorrules` (положить в корень репозитория)

```
Ты работаешь над проектом "AI Context-Buyer Platform" — мультиагентной
SaaS-платформой, автоматизирующей полный цикл работы контекстолога
(Яндекс Директ, Google Ads) для множества клиентских проектов.

Ключевые архитектурные принципы, которые нужно соблюдать в любом коде:

1. Мультиклиентская изоляция: любые данные, токены, кампании привязаны к
   project_id. Никогда не пиши код, который смешивает данные разных проектов
   или использует общие/глобальные учётные данные для клиентских операций.

2. Connector Layer как единственная точка доступа к внешним рекламным API.
   Бизнес-логика (агенты, оркестратор) никогда не вызывает SDK Яндекс Директа
   или Google Ads напрямую — только через интерфейс AdPlatformConnector.

3. Каждый AI-агент — узкая функция с валидируемым JSON-схемой входом/выходом.
   Не пиши "монолитных" агентов, которые сразу и парсят семантику, и пишут
   тексты, и принимают решения о бюджете.

4. Оркестрация пайплайна — детерминированный код (state machine / очередь
   задач), а не LLM, решающий "что делать дальше". LLM вызывается только
   внутри конкретных шагов с чётко ограниченной задачей.

5. Никаких автоматических публикаций рекламных кампаний без явного
   подтверждения пользователя, пока не сказано обратное в задаче.

6. Секреты (OAuth-токены, API-ключи) никогда не хардкодятся и не пишутся
   в логи в открытом виде — только через переменные окружения/secret manager
   и с шифрованием в БД.

Перед реализацией новой фичи — свериться с документами в /docs (PRD,
архитектура, спецификация агентов, модели данных) и не выходить за рамки
текущего этапа роадмапа, если явно не попросили иначе.

Стиль кода: TypeScript strict mode (или типизированный Python с pydantic),
покрытие тестами бизнес-логики агентов и Connector Layer обязательно.
```

## 3. Практические советы по промптам для Cursor Agent

- **Начинайте узко.** Пример хорошего первого промпта:
  "Открой /docs/03_DATA_MODELS.md и /docs/06_TECH_STACK.md. Сгенерируй
  Postgres-миграции для таблиц organizations, users, projects,
  ad_platform_credentials, project_briefs по схеме из раздела 1. Используй
  [Prisma/Drizzle/SQLAlchemy — выбрать инструмент]."
- **Не просите "построй всю платформу" одним промптом.** Мультиагентная
  система с внешними интеграциями требует пошаговой сборки с проверкой на
  каждом шаге — иначе агент сгенерирует правдоподобно выглядящий, но не
  интегрированный между собой код.
- **Явно указывайте, какой документ читать.** Cursor Agent работает точнее,
  когда вы говорите "используй контракт из 05_AI_AGENTS_SPEC.md раздел 3",
  чем когда просто описываете задачу словами заново.
- **Просите тесты сразу вместе с реализацией**, особенно для
  `Connector Layer` — эти модули дороже всего чинить постфактум, так как
  ошибки проявляются на реальных рекламных аккаунтах.
- **Для интеграций с внешними API** (Яндекс Директ, Google Ads) — просите
  Cursor сначала сгенерировать mock-реализацию `AdPlatformConnector`
  (возвращает фиктивные данные), чтобы можно было разрабатывать и тестировать
  агентов до получения реальных API-доступов.
